Overview

Direct interaction with the operating system kernel through system calls

Exit Syscall

Using the syscall()

Key Concepts:

  • Exit Codes: Programs return a status code to the shell (0 = success, non-zero = error)
  • System Call Numbers: Each system call has a unique number (SYS_exit is defined in system headers)
  • No Return: The exit system call terminates the process, so code after it never executes
  • syscall() Wrapper: This libc function provides a generic interface to make any system call

Reference: Cornell ECE - Assembler in GCC

C Code

#include <unistd.h>
#include <sys/syscall.h>

int main() {
    syscall(SYS_exit, 42);
    return 0;  // Never reached
}

Write Syscall

Using the write() system call to output text directly to stdout. This bypasses the standard library and talks directly to the kernel.

Key Concepts:

  • System Calls: A mechanism for user programs to request services from the kernel
  • File Descriptors: File descriptor 1 is standard output (stdout)
  • Direct Kernel Access: Unlike printf which uses buffered I/O, write() goes straight to the kernel
  • Calling Convention: System calls on Linux use the syscall instruction with arguments in specific registers

Reference: GCC Documentation - Using Assembly Language with C

C Code

#include <unistd.h>

int main() {
    const char msg[] = "Hello from syscall\n";
    write(1, msg, sizeof(msg) - 1);
    return 0;
}
